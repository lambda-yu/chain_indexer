# Chain Indexer — M2 Design Spec

**Date:** 2026-05-26
**Status:** Draft (pending spec-reviewer pass)
**Parent spec:** `2026-05-25-chain-indexer-design.md`
**Builds on:** `m1-complete` tag (EVM native transfer → HTTP webhook)

## 1. Purpose

M2 closes the spec §3 functional gap left by M1:
- All four parser kinds (native, standard token, ABI event, ABI call) work on EVM.
- The same four kinds work on Solana via a new `SolanaAdapter`.
- Two additional notification channels (Redis Streams MQ, WebSocket fanout) join the existing HTTP webhook channel.
- M1's nine deferred follow-ups are cleared in a dedicated cleanup chunk.

The shape of the system does not change — M1's adapter → confirmation → parser pipeline → matcher → notifier topology stays intact. M2 only fills slots that the M1 plan explicitly left open.

## 2. In Scope / Out of Scope

### In scope (M2)

**EVM segment** (chunks 1–9):
1. M1-deferred follow-ups cleanup (9 items, see §9.1).
2. ABI entity API + registry + decoder cache (`core/abi/`).
3. `Erc20TransferParser` — standard ERC-20 `Transfer(address,address,uint256)` log decoding.
4. `AbiEventParser` — user-uploaded ABI; index by `topic0`.
5. `AbiCallParser` — user-uploaded ABI; index by 4-byte selector; consumes tx `input`.
6. `Channel` ABC strict contract (`__init_subclass__` enforcement; init-arg shape pinned).
7. `RedisStreamsChannel` — pluggable Redis Streams MQ driver.
8. `WebSocketChannel` + `/ws?channel_id=` server with Redis `ws_fanout` pubsub.
9. EVM-segment IT convergence (full multi-parser, multi-channel flow).

**Solana segment** (chunks 10–14):
10. `SolanaAdapter` — RPC + commitment levels (`confirmed`/`finalized`) instead of `ConfirmationBuffer`; emits a `SolanaBlock` payload (still consumed by the shared parser pipeline).
11. `SolNativeTransferParser` — System Program transfers.
12. `SplTransferParser` — Token Program 2022 + legacy Token Program transfers.
13. `AnchorIdlEventParser` — discriminator-indexed Anchor IDL event decoder.
14. Solana E2E using `solana-test-validator`.

`arg_filters` semantics are also tightened in this milestone (currently a pass-through dict; M2 makes it a typed equality filter per spec §3 / §5.3).

### Out of scope (M2 — deferred to M3+)

- Reorg E2E driving real Anvil snapshot rollbacks. (`ConfirmationBuffer` unit tests stay authoritative; an E2E lands when we have a concrete production incident to reproduce.)
- Anchor IDL **call** parsing. (Anchor program calls share the same discriminator layout as events but require IDL `instructions[]` walking; deferred so M2 ships one Solana parser at a time.)
- Additional MQ brokers — RabbitMQ, Kafka, NATS. (The `Channel` ABC is the extension point; adding a driver is a single chunk in M3 when a user actually needs it.)
- Auth on the management API and the WebSocket server. (No-auth design is a spec §2 non-goal; M2 inherits it.)
- WebSocket replay / backfill. (`/ws` only fans out live events. Backfill from `events` table is M5 observability work.)
- Web UI screens for ABI upload and channel configuration. (Static UI is a separate milestone.)
- Per-chain horizontal sharding. (Single-worker is fine until block-rate forces it.)

## 3. Architecture Deltas

M1's component map (`adapter → confirmation buffer → parser pipeline → matcher → notifier`) is unchanged. M2 adds the boxes marked `[+]`:

```
[Web]                                    [Worker]
  ├─ REST: chains/channels/subs           ├─ ChainListener
  ├─ REST: abis            [+]            │     ├─ EvmAdapter
  ├─ /ws?channel_id=       [+]            │     │     └─ ConfirmationBuffer
  └─ Redis sub on ws_fanout [+]           │     └─ SolanaAdapter   [+]
                                          │           └─ commitment-level filter
                                          ├─ ParserPipeline
                                          │     ├─ NativeTransferParser
                                          │     ├─ Erc20TransferParser    [+]
                                          │     ├─ AbiEventParser         [+]
                                          │     ├─ AbiCallParser          [+]
                                          │     ├─ SolNativeTransferParser [+]
                                          │     ├─ SplTransferParser       [+]
                                          │     └─ AnchorIdlEventParser    [+]
                                          ├─ Matcher (arg_filters tightened) [+]
                                          └─ Notifier
                                                ├─ HttpChannel
                                                ├─ RedisStreamsChannel [+]
                                                └─ WebSocketChannel    [+]
```

Two cross-cutting modules:

- **`core/abi/`** *(new)* — registry + decoder cache shared by `AbiEventParser`, `AbiCallParser`, and (eventually) `AnchorIdlEventParser`. Loads `abis.body` on demand, caches compiled `eth_abi` codecs per `(abi_id, selector)`, and exposes a `get_event_decoder(abi_id, topic0)` / `get_call_decoder(abi_id, selector)` API.
- **`core/chains/solana.py`** *(new)* — `SolanaAdapter` implements `ChainAdapter` but ignores `ConfirmationBuffer`. It polls `getBlock` at the configured commitment level (`confirmed` or `finalized`); reorgs at those commitments are vanishingly rare and the buffer would only add latency. It emits a `SolanaBlock` (different concrete shape than EVM `Block`) but parsers receive a uniform `Block | SolanaBlock` union so the pipeline doesn't branch on chain kind.

## 4. Components — Detailed

### 4.1 `core/abi/`

```
core/abi/
  registry.py   # async load by abi_id; LRU cache; invalidate on config_changed
  decoder.py    # eth_abi-backed event/call decoders (EVM); borsh for Anchor
  errors.py     # AbiNotFound, DecodeFailed
```

- `AbiRegistry` is constructed once per worker, takes a `Database` handle, and refreshes its in-memory map when `config_watcher` fires.
- Decoders cache by `(abi_id, key)` where `key` is `topic0` for events / 4-byte selector for calls / 8-byte discriminator for Anchor IDL.
- On decode failure, parsers downgrade output to `kind="log"` with the raw payload (spec §8 fallback).

### 4.2 EVM parsers

All three follow the existing `Parser` interface (spec §6). Test seams:

- `Erc20TransferParser` — given a block with synthetic `Transfer` logs, asserts decoded args `{from, to, value}` and `kind="token_transfer"`.
- `AbiEventParser` — uses a fixture ABI; asserts decoded args by name; asserts unknown-topic downgrade to `kind="log"`.
- `AbiCallParser` — consumes `tx.input`; asserts decoded function name + args; asserts unknown-selector skip (NOT downgrade — call parser is opt-in per subscription).

### 4.3 `Channel` ABC strictness

M1's `core/notifier/channel.py` has a loose interface (subclasses define `type` as a class attr by convention). M2 enforces it via `__init_subclass__`:

```python
class Channel(ABC):
    type: ClassVar[str]  # must be set by every subclass

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if not isinstance(getattr(cls, "type", None), str):
            raise TypeError(f"{cls.__name__} must declare a `type: str` class attribute")

    @abstractmethod
    async def send(self, payload: dict) -> None: ...
```

Registry collisions also raise at import time, not at first delivery.

### 4.4 `RedisStreamsChannel`

- Config: `{stream: str, maxlen: int | None}`. Optional `maxlen` invokes `XADD ... MAXLEN ~ N` to cap stream length.
- Uses the existing `RedisBus` connection (M1 already holds an `aioredis.Redis` instance).
- Payload: same `event_payload` shape as HTTP (spec §8); serialized as JSON in a `data` field of the stream entry.
- Retry: 3 attempts with exponential backoff (matches `HttpChannel`).

### 4.5 `WebSocketChannel` + `/ws` server

- Channel config: `{ws_fanout_channel: str}` — a Redis pubsub channel name that the WS server subscribes to.
- `WebSocketChannel.send(payload)` → `redis.publish(ws_fanout_channel, json.dumps(payload))`.
- `/ws?channel_id=<uuid>` handler in `apps/web/routers/ws.py`:
  - Resolves `channel_id` → `ws_fanout_channel` via `ChannelRepo`.
  - Subscribes to that Redis pubsub channel.
  - Streams every published message to the connected client until disconnect.
  - Multiple clients per `channel_id` allowed (Redis pubsub fans out natively).
- Drops messages if the client buffer is full (slow-consumer protection); does not retry per-client.

### 4.6 `SolanaAdapter`

```python
class SolanaAdapter:
    chain_id: str
    commitment: Literal["confirmed", "finalized"]   # from chain config

    async def subscribe_heads(self) -> AsyncIterator[BlockHeader]: ...
    async def fetch_block(self, slot: int) -> SolanaBlock: ...
    async def get_latest_block(self) -> int: ...
```

- RPC client: `solders` for type-safe RPC + `httpx.AsyncClient` for transport. No `solana-py` dependency.
- `subscribe_heads` polls `getSlot` at the configured commitment every `poll_interval_ms`.
- `fetch_block` calls `getBlock` with `maxSupportedTransactionVersion=0`, `transactionDetails="full"`, `rewards=false`.
- No `ConfirmationBuffer` — commitment level guarantees finality at the configured level.
- `SolanaBlock` shape: `slot`, `block_hash`, `block_time`, `transactions: list[SolanaTransaction]`. Each tx carries `meta.pre_balances`, `meta.post_balances`, `meta.log_messages`, `transaction.message.account_keys`, `transaction.message.instructions`.

### 4.7 Solana parsers

- `SolNativeTransferParser` — walks `instructions` for `system_program::transfer`; emits `kind="native_transfer"` with `{from, to, value}` in lamports.
- `SplTransferParser` — walks `instructions` for `spl_token::Transfer` / `spl_token_2022::Transfer`; emits `kind="token_transfer"`; resolves mint via `pre/post_token_balances`.
- `AnchorIdlEventParser` — scans `meta.log_messages` for `Program data: ...` lines; base64-decodes; first 8 bytes is the discriminator; looks up event schema in `AbiRegistry`; borsh-decodes the rest.

### 4.8 `arg_filters` tightening

M1 leaves `arg_filters: dict` as a pass-through (validated to be a dict, not used by the matcher). M2:

- Pydantic schema validates `arg_filters` is `dict[str, str | int | bool]` (equality values only — spec §3 says "simple equality filters").
- Matcher compares decoded `event.args[k] == arg_filters[k]` for every key in `arg_filters` (must all match).
- Type coercion: `int` filter against an `int` arg works directly; `str` filter against an `int` arg fails the match (no implicit coercion). Addresses are compared lowercase on EVM.

## 5. Data Flow — Per Chain Kind

### EVM (unchanged from M1, with new parsers in the pipeline)

```
EvmAdapter → BlockHeader → ConfirmationBuffer → confirmed Block
  → ParserPipeline (native, erc20, abi_event, abi_call all consume same Block)
  → Event[]
  → Matcher (chain_id, address, match_kind, match_name, arg_filters)
  → (Subscription, [Channel]) pairs
  → Notifier → Channel.send(payload)
```

### Solana

```
SolanaAdapter (commitment-bound poll) → SolanaBlock
  → ParserPipeline (sol_native, spl, anchor_event consume SolanaBlock)
  → Event[] (same uniform shape)
  → Matcher (same code path; chain_id picks Solana subs)
  → Notifier → Channel.send(payload)
```

The matcher does not branch on chain kind — both shapes emit the same `Event` dataclass.

## 6. Error Handling Deltas

| Failure | M2 behavior |
|---|---|
| ABI missing for `abi_id` referenced by a subscription | Log warning, skip parsing that subscription's matches; do NOT block the pipeline. |
| ABI decode failure | Downgrade to `kind="log"` with raw payload (spec §8 fallback). Already specced; M2 implements. |
| Solana RPC 429 / timeout | Same retry policy as EVM (`tenacity` exponential backoff, max 3). After max retries, log and skip block (checkpoint is NOT advanced — the next poll retries from the same slot). |
| WebSocket client buffer full | Server drops the message for that client (no per-client retry). Other clients on the same channel are unaffected. |
| Redis Streams `MAXLEN ~` trimming | Best-effort; trim failures log a warning but do not fail the delivery. |
| Anchor IDL discriminator collision (rare but possible across programs) | Resolve by program ID — `AnchorIdlEventParser` checks the instruction's `program_id` matches the `abi`'s declared program. |

## 9. Open Decisions / Risks

### 9.1 The nine M1 follow-ups (chunk 1)

Bundled into a single cleanup pass to avoid scattering:

1. Parallel `_Worker.shutdown` runner stops (use `asyncio.gather` over per-chain runners).
2. `Notifier._sem` event-loop binding (build on first use, not in `__init__`).
3. `Channel` ABC contract — handled as part of chunk 6, not chunk 1.
4. `Channel.type` `__init_subclass__` enforcement — also chunk 6.
5. `arg_filters` value-shape validation — handled in chunk 9.
6. `poll_interval_ms` per-chain plumbing into `EvmAdapter`.
7. Session-scope Redis fixture once test count grows (defer the move to session scope until chunk-9 test count justifies it; track only).
8. Friendlier `KeyError` / Windows signal handler docstring polish.
9. Deterministic worker-ready signal in E2E (replace `await asyncio.sleep(1.0)`).

Items 3, 4, 5 graduate into later chunks where they fit better. Chunk 1 closes the other six.

### 9.2 Risks

- **`solders` API churn.** `solders` is the modern Solana Python client but its API is less stable than `web3.py`. Risk: a version bump breaks the adapter. Mitigation: pin to a tested minor version; add `solders` to dev deps with a tight constraint; rely on `solana-test-validator` IT for early breakage detection.
- **Anchor IDL discriminator collisions.** Across multiple programs, two different events could share an 8-byte discriminator (probability vanishingly low but non-zero). Mitigation: scope discriminator lookup to a specific `program_id` per `AbiRegistry` entry (see §6).
- **WebSocket back-pressure.** Slow clients can hold up Redis pubsub fanout. Mitigation: per-client async queue with bounded size; drop-on-full with a single logged warning per client per minute.
- **`arg_filters` semantics break existing M1 subscriptions.** M1 accepts arbitrary dicts. Strict typing in M2 could reject existing data. Mitigation: migration step in chunk 9 validates existing rows and either auto-cleans empties or surfaces a list of subs to fix.
- **`solana-test-validator` cold-start time** in E2E (5–10s vs Anvil's <1s). Mitigation: scope it as session-scoped fixture (different from M1's function-scoped `anvil`); document slower local feedback.

### 9.3 Things deliberately deferred and why

- **Persisted `events` table for replay.** Spec §10 mentions it for observability/M5. M2 stays stateless on the event stream because adding persistence here would couple the notifier to DB latency and obscure delivery semantics.
- **Per-channel retry policy customization.** M2 inherits the M1 hard-coded `3 attempts, exponential backoff`. Per-channel YAML knobs are an M3 ergonomic improvement.
- **Anchor IDL call parser.** Skipped because Anchor instruction decoding requires walking `instructions[]` with account-key resolution; doing it right takes its own chunk. The event parser handles 80%+ of observability use cases.

---

This M2 design closes the parsing and channel gaps in the spec while keeping M1's pipeline backbone unchanged. Each chunk produces a tagged green-tests state.
