# M3 Design Spec: Solana Parsing Completeness + Operational Maturity

## 1. Goal

Complete the Solana parsing surface to near-EVM parity and harden the notification channel layer with config validation, per-channel retry tuning, and WS-based head subscription.

## 2. Scope

Seven deliverables in three segments:

| # | Segment | Deliverable | Key files |
|---|---------|-------------|-----------|
| 1 | A (Solana parsing) | borsh nested/composite type support | `core/abi/decoder.py` |
| 2 | A | Anchor IDL call parser | `core/parser/anchor_call.py`, `core/abi/registry.py` |
| 3 | A | SPL `transferWithFee` (Token-2022) | `core/parser/spl_transfer.py` |
| 4 | A | SPL non-Transfer ops (Approve/Revoke/MintTo/Burn) | `core/parser/spl_ops.py` |
| 5 | B (Ops maturity) | Channel config JSON-schema validation | `core/notifier/channel.py`, channel subclasses |
| 6 | B | Per-channel retry policy | `core/notifier/retry.py`, channel subclasses |
| 7 | B | Solana WS head subscription | `core/chains/solana.py` |

## 3. Out of scope (M4+)

- EVM internal/sub-call tracing (`trace_block` RPC)
- Multi-ABI topic0 fan-out (collision handling beyond first-write-wins)
- Auth on management API / WebSocket server
- Persisted events table / replay
- Per-chain horizontal sharding
- Web UI
- Additional MQ brokers (Kafka/RabbitMQ) — lands when a user needs it

## 4. Detailed design

### 4.1 Chunk 1: borsh nested/composite type support

**Problem.** M2's `build_anchor_event_struct` only handles flat scalar types. IDL events or instructions using `{defined: "MyStruct"}`, `{vec: "u64"}`, `{option: "pubkey"}`, or `{array: ["u8", 32]}` are logged-and-skipped.

**Design.** Replace the flat `_ANCHOR_SCALAR_MAP` lookup with a recursive `_resolve_type(type_spec, types_section)` function:

- `str` scalar → existing `_ANCHOR_SCALAR_MAP[scalar]` (unchanged)
- `{"defined": name}` → look up `name` in `idl["types"]`, recursively synthesize a `CStruct` from its `fields`
- `{"vec": inner}` → `borsh_construct.Vec(_resolve_type(inner, types_section))`
- `{"option": inner}` → `borsh_construct.Option(_resolve_type(inner, types_section))`
- `{"array": [inner, size]}` → `construct.Array(size, _resolve_type(inner, types_section))`
- Anything else → return `None` (caller logs and skips the event/instruction)

Circular `defined` references are guarded by a `seen: set[str]` parameter; a cycle returns `None`.

`decode_anchor_event` post-processing extends: nested `Container` objects are recursively converted to plain `dict`; `Vec` results become `list`; 32-byte `bytes` inside nested structs are also base58-encoded.

**Testing.** Unit tests with a synthetic IDL containing nested struct, vec-of-pubkey, option-of-u64, and array-of-u8. One test for circular-ref detection (returns `None`, no crash).

### 4.2 Chunk 2: Anchor IDL call parser

**Problem.** M2 ships `AnchorIdlEventParser` (decodes `emit!` macro events from `Program data:` log lines) but not the call-side counterpart. Anchor program instructions use a different discriminator namespace: `sha256("global:<fn_name>")[:8]` (vs `sha256("event:<name>")[:8]` for events).

**Design.**

New file `core/parser/anchor_call.py` with class `AnchorIdlCallParser`:

- Consumes `SolanaBlock`. Walks `block.transactions[].instructions[]`.
- For each instruction at `stack_depth == 1` whose `program_id` resolves in the registry:
  1. Base58-decode `ix.data_b58`.
  2. Extract first 8 bytes as the call discriminator.
  3. Look up `(program_id, disc_hex)` in the registry's new call-discriminator index.
  4. If found: borsh-decode the remaining bytes using the matched struct → emit `Event(kind="call", name=<fn_name>, contract=program_id, args=<decoded>)`.
  5. If not found: skip silently (same policy as EVM `AbiCallParser`).
  6. If decode fails: log warning + skip.
- Skips failed transactions (`tx.success is False`).

**Registry changes.** `AbiRegistry` gains:
- `_anchor_call_index: dict[tuple[str, str], tuple[str, str, Any]]` — `(program_id, disc_hex) → (abi_id, fn_name, struct)`.
- `_rebuild_anchor_call_index()` called from `refresh()` — reads `idl["instructions"]` (not `idl["events"]`), computes `sha256("global:<name>")[:8]`.
- `lookup_idl_call_by_discriminator(program_id, disc_hex) → tuple[str, Any] | None`.
- New decoder helper: `anchor_call_discriminator(fn_name: str) -> bytes` = `sha256(f"global:{fn_name}".encode()).digest()[:8]`.

**ChainRunner wiring.** When `abi_registry` is set, the Solana pipeline appends `AnchorIdlCallParser` after `AnchorIdlEventParser`.

### 4.3 Chunk 3: SPL `transferWithFee` (Token-2022)

**Problem.** `SplTransferParser` handles discriminators 3 (`Transfer`) and 12 (`TransferChecked`). Token-2022's `TransferCheckedWithFee` (discriminator 26) carries an additional `fee: u64` and `fee_decimals: u8` after the amount.

**Design.** Extend `SplTransferParser._decode`:
- Discriminator 26, data layout: `[1 byte disc] [8 bytes amount u64 LE] [1 byte decimals] [8 bytes fee u64 LE] [1 byte fee_decimals]` = 19 bytes total.
- Accounts: `[source, mint, dest, authority]` (same as `TransferChecked`).
- Emit same `kind="token_transfer"` Event. `args` gains optional `"fee": str(fee)` when present.
- Existing Transfer/TransferChecked events continue to omit `fee` (no breaking change).

### 4.4 Chunk 4: SPL non-Transfer operations

**Problem.** SPL Token Program operations beyond Transfer are invisible to the indexer.

**Design.** New file `core/parser/spl_ops.py` with class `SplOpsParser`:

| Discriminator | Name | Accounts | Decoded args |
|--------------|------|----------|--------------|
| 4 | `approve` | `[source, delegate, owner]` | `{source, delegate, amount}` |
| 5 | `revoke` | `[source, owner]` | `{source}` |
| 7 | `mint_to` | `[mint, dest, authority]` | `{mint, dest, amount}` |
| 8 | `burn` | `[source, mint, owner]` | `{source, mint, amount}` |

- All emit `kind="call"`, `contract=<mint or source>`, `name=<op_name>`.
- All require `tx.success is True` and `stack_depth == 1`.
- Mint is resolved from accounts (position depends on instruction) or fallback to `post_token_balances`.
- Handles both legacy Token Program and Token-2022 Program IDs.

**ChainRunner wiring.** `SplOpsParser` appended to Solana pipeline after `SplTransferParser`.

### 4.5 Chunk 5: Channel config JSON-schema validation

**Problem.** Channel `config` blobs are accepted as `dict[str, Any]` and only fail at runtime when a required key is missing (e.g., `KeyError: 'stream'` in `RedisStreamsChannel.__init__`).

**Design.**
- Each `Channel` subclass declares `config_schema: ClassVar[dict[str, Any]]` as a JSON Schema dict.
- `Channel.__init_subclass__` is extended to also validate `config_schema` presence (alongside existing `type` check).
- API layer (`POST /api/channels`): after Pydantic validation passes, run `jsonschema.validate(payload.config, CHANNEL_REGISTRY[payload.type].config_schema)`. On failure: 422 with the JSON Schema error message.
- Add `jsonschema>=4.20,<5` to project dependencies.

Schemas for existing channels:

- **HTTP:** `{"type": "object", "required": ["url"], "properties": {"url": {"type": "string"}, "method": {"type": "string"}, "headers": {"type": "object"}, "hmac_secret": {"type": "string"}, "timeout_seconds": {"type": "number"}}}`
- **MQ:** `{"type": "object", "required": ["stream"], "properties": {"stream": {"type": "string"}, "maxlen": {"type": "integer"}}}`
- **WS:** `{"type": "object", "required": ["ws_fanout_channel"], "properties": {"ws_fanout_channel": {"type": "string"}}}`

### 4.6 Chunk 6: Per-channel retry policy

**Problem.** All channels share a hard-coded `max_attempts=3, base_delay=1.0` retry policy. Operators can't tune per-channel.

**Design.**
- Channel `config` gains an optional `"retry"` sub-object: `{"max_attempts": int, "base_delay": float, "backoff_factor": float}`.
- `Channel` base class provides a `_retry_config` property that reads from `self._config.get("retry", {})` with defaults `(3, 1.0, 4.0)`.
- Each channel's `send()` passes `self._retry_config` values to `retry_with_backoff(...)`.
- JSON schemas (from chunk 5) are extended with the optional `retry` property.
- No DB migration — retry config lives inside the existing JSON `config` column.

### 4.7 Chunk 7: Solana WS head subscription

**Problem.** `SolanaAdapter.subscribe_heads()` polls `getSlot` via HTTP at `poll_interval_ms`. This adds latency (up to one poll interval) and wastes RPC calls when no new slot has been produced.

**Design.**
- When `SnapshotChain.rpc_ws` is not None, `SolanaAdapter` uses WebSocket `slotSubscribe` for real-time slot notifications.
- The `subscribe_heads()` method checks `self._rpc_ws`:
  - **WS mode:** Connect to `rpc_ws`, send `slotSubscribe`, yield each `slot` from the subscription stream. On disconnect: log warning, fall back to HTTP polling loop until WS reconnects.
  - **HTTP mode (fallback):** Existing `_poll_heads()` logic, unchanged.
- WS reconnect uses exponential backoff (1s → 4s → 16s, capped at 60s). A successful reconnect resets the backoff.
- Uses `websockets` library (already a transitive dep of `web3`).

## 5. Delivery order

Segments ship in order: A (chunks 1-4) then B (chunks 5-7). Within each segment, chunks are sequential. Rationale:

- Chunk 1 (nested types) unblocks chunk 2 (Anchor call parser uses the same synthesizer).
- Chunk 5 (config schema) unblocks chunk 6 (retry config extends the schema).
- Chunk 7 (WS head) is independent but last because it's the highest-risk change (new transport layer).

## 7. Dependencies

New runtime dependency: `jsonschema>=4.20,<5` (chunk 5 only).

No other new deps. `websockets` is already transitively available via `web3`.

## 8. Risks

- **borsh nested types (chunk 1):** Recursive IDL schemas can be deeply nested. The `seen` set guards against infinite recursion, but pathological IDLs with 10+ levels may produce large `CStruct` trees. Mitigation: cap recursion depth at 8 levels; log and skip beyond that.
- **Solana WS stability (chunk 7):** Public RPC providers may throttle or drop WS connections. The fallback-to-HTTP design ensures liveness; the risk is increased latency during WS reconnect windows, not data loss.
- **SPL discriminator drift (chunks 3-4):** SPL Token Program discriminators are stable (no Anchor IDL — they're hand-coded in the Solana Program Library). Risk is low but a new Token-2022 extension instruction could add a colliding discriminator. Mitigation: the parser skips unknown discriminators silently.
