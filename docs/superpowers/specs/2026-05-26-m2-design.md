# Chain Indexer — M2 Design Spec

**Date:** 2026-05-26
**Status:** Draft (pending spec-reviewer pass)
**Parent spec:** `2026-05-25-chain-indexer-design.md`
**Builds on:** `m1-complete` tag (EVM native transfer → HTTP webhook)

## 1. Purpose

M2 closes the spec §3 functional gap left by M1:
- All four parser kinds (native, standard token, ABI event, ABI call) work on EVM.
- The same four kinds work on Solana via a new `SolanaAdapter`.
- Two additional notification channels (Redis Streams MQ, WebSocket fanout) join the existing HTTP webhook channel.
- M1's deferred follow-ups are cleared (six in a dedicated cleanup chunk, two graduate into chunks that touch their files, one tracked-only per §9.1).

The shape of the system does not change — M1's adapter → confirmation → parser pipeline → matcher → notifier topology stays intact. M2 only fills slots that the M1 plan explicitly left open.

## 1a. What M1 Already Shipped (Anti-Drift Cheat Sheet)

To avoid repeating the spec-reviewer's catches, here's what is **already in tree** and therefore NOT new work in M2 (with file references):

- `core/matcher/filters.py` — full filter grammar `eq` / `_in` / `_gte` / `_lte`, with case-insensitive string compare and typo rejection. M2 does NOT redesign this; it only tightens the Pydantic value-type at the API boundary (see §4.8).
- `core/matcher/matcher.py:31` indexes subs by `(chain_id, match_kind)` and calls `evaluate(sub.arg_filters or {}, event.args)` (line 52). Matcher logic stays.
- `core/notifier/channel.py:15` — `Channel` ABC already declares `type: ClassVar[str]`. `core/notifier/__init__.py` uses a `register_channel(cls)` decorator that raises on duplicate. M2's chunk 6 only **adds** `__init_subclass__` so subclasses can't forget either the `type` attribute or the registration call (see §4.3).
- `core/notifier/retry.py` — generic retry primitive with exponential backoff. `RedisStreamsChannel` (chunk 7) and `WebSocketChannel` (chunk 8) **reuse** it; they do not fork it.
- `core/parser/event.py:6` — `EventKind = Literal["native_transfer", "token_transfer", "log", "call"]`. **This disagrees with `MatchKind` (`core/config/models.py:36`), which has `event` instead of `log`.** M2 resolves the drift in chunk 4 (see §4.9 below) by **renaming `EventKind.log → event`** so the matcher's `(chain_id, kind)` key works across EVM/Solana ABI parsers.
- `core/config/models.py:78` — `Abi` table exists (`id`, `name`, `kind: evm_abi | solana_idl`, `body: json`). M2 does NOT add the table; it adds the CRUD API + the runtime registry (chunk 2).
- `apps/worker/main.py:24` — `_default_adapter_factory` already branches on `cfg.kind` and `raise NotImplementedError` for non-evm. M2 chunk 10 extends this branch to construct `SolanaAdapter`.
- `core/parser/native.py` docstring claims "the SolanaAdapter is responsible for shaping native transfers into Tx entries". **This claim is retracted by M2.** Solana parsers consume `SolanaBlock` directly (different shape than EVM `Block`); chunk 11 ships a dedicated `SolNativeTransferParser`. The misleading docstring is corrected in chunk 1 cleanup.

**Solana segment** (chunks 10–14):

### Out of scope (M2 — deferred to M3+)

- Reorg E2E driving real Anvil snapshot rollbacks. (`ConfirmationBuffer` unit tests stay authoritative; an E2E lands when we have a concrete production incident to reproduce.)
- Anchor IDL **call** parsing. (Anchor program calls share the same discriminator layout as events but require IDL `instructions[]` walking; deferred so M2 ships one Solana parser at a time.)
- Additional MQ brokers — RabbitMQ, Kafka, NATS. (The `Channel` ABC is the extension point; adding a driver is a single chunk in M3 when a user actually needs it.)
- Auth on the management API and the WebSocket server. (No-auth design is a spec §2 non-goal; M2 inherits it.)
- WebSocket replay / backfill. (`/ws` only fans out live events. Backfill from `events` table is M5 observability work.)
- Web UI screens for ABI upload and channel configuration. (Static UI is a separate milestone.)
- Per-chain horizontal sharding. (Single-worker is fine until block-rate forces it.)

## 3. Architecture Deltas

M1's component map (`adapter → confirmation buffer → parser pipeline → matcher → notifier`) is unchanged. M2 adds the boxes marked `[+]`:

```
[Web]                                    [Worker]
  ├─ REST: chains/channels/subs           ├─ ChainListener
  ├─ REST: abis            [+]            │     ├─ EvmAdapter
  ├─ /ws?channel_id=       [+]            │     │     └─ ConfirmationBuffer
  └─ Redis sub on ws_fanout [+]           │     └─ SolanaAdapter   [+]
                                          │           └─ commitment-level filter
                                          ├─ ParserPipeline
                                          │     ├─ NativeTransferParser
                                          │     ├─ Erc20TransferParser    [+]
                                          │     ├─ AbiEventParser         [+]
                                          │     ├─ AbiCallParser          [+]
                                          │     ├─ SolNativeTransferParser [+]
                                          │     ├─ SplTransferParser       [+]
                                          │     └─ AnchorIdlEventParser    [+]
                                          ├─ Matcher (arg_filters tightened) [+]
                                          └─ Notifier
                                                ├─ HttpChannel
                                                ├─ RedisStreamsChannel [+]
                                                └─ WebSocketChannel    [+]
```

Two cross-cutting modules:

- **`core/abi/`** *(new)* — registry + decoder cache shared by `AbiEventParser`, `AbiCallParser`, and (eventually) `AnchorIdlEventParser`. Loads `abis.body` on demand, caches compiled `eth_abi` codecs per `(abi_id, selector)`, and exposes a `get_event_decoder(abi_id, topic0)` / `get_call_decoder(abi_id, selector)` API.
- **`core/chains/solana.py`** *(new)* — `SolanaAdapter` implements `ChainAdapter` but ignores `ConfirmationBuffer`. It polls `getBlock` at the configured commitment level (`confirmed` or `finalized`); reorgs at those commitments are vanishingly rare and the buffer would only add latency. It emits a `SolanaBlock` (different concrete shape than EVM `Block`) but parsers receive a uniform `Block | SolanaBlock` union so the pipeline doesn't branch on chain kind.

## 4. Components — Detailed

### 4.1 `core/abi/`

```
core/abi/
  registry.py   # async load by abi_id; LRU cache; invalidate on config_changed
  decoder.py    # eth_abi-backed event/call decoders (EVM); borsh-construct for Anchor IDL
  errors.py     # AbiNotFound, DecodeFailed
```

- `AbiRegistry` is constructed once per worker, takes a `Database` handle, and refreshes its in-memory map when `config_watcher` fires.
- Decoders cache by `(abi_id, key)` where `key` is `topic0` for events / 4-byte selector for calls / 8-byte discriminator for Anchor IDL.
- ABI lookup is **per-event** at decode time (parsers receive an `Event`-shaped intermediate that carries the `abi_id` via the subscription map; no startup-time pre-binding of ABI IDs into parser instances). This keeps the matcher loop the single point of `subscription → abi_id` resolution and means a freshly-added ABI is observable on the very next block without rebuilding the pipeline.
- Anchor decoding library: **`borsh-construct`** — chosen over `anchorpy` to avoid the full Anchor client surface; we only need schema-driven deserialization. Pinned to a tested minor.
- On decode failure, parsers downgrade output to `kind="log"` with the raw payload (spec §8 fallback). For Solana, "raw payload" means the original `Program data: ...` base64 string preserved in `event.raw`.

### 4.2 EVM parsers

All three follow the existing `Parser` interface (spec §6). Test seams:

- `Erc20TransferParser` — given a block with synthetic `Transfer` logs, asserts decoded args `{from, to, value}` and `kind="token_transfer"`.
- `AbiEventParser` — uses a fixture ABI; asserts decoded args by name; asserts unknown-topic downgrade to `kind="log"`.
- `AbiCallParser` — consumes `tx.input`; asserts decoded function name + args; asserts unknown-selector skip (NOT downgrade — call parser is opt-in per subscription).

### 4.3 `Channel` ABC strictness

M1 already has the `Channel` ABC with `type: ClassVar[str]` and a `register_channel(cls)` decorator that raises on duplicate registrations (`core/notifier/channel.py:15`, `__init__.py`). The remaining loose seam is that subclasses can be defined without ever calling `register_channel`, and the missing entry surfaces only at first use. M2's chunk 6 closes that by **adding `__init_subclass__`**:

```python
class Channel(ABC):
    type: ClassVar[str]

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        if not isinstance(getattr(cls, "type", None), str):
            raise TypeError(f"{cls.__name__} must declare a `type: str` class attribute")
        register_channel(cls)   # auto-register; raises on duplicate type
    ...
```

The existing `register_channel` decorator stays callable for explicit registration in tests (idempotent on same-class re-registration). The duplicate-type check is unchanged.

### 4.4 `RedisStreamsChannel`

- Config: `{stream: str, maxlen: int | None}`. Optional `maxlen` invokes `XADD ... MAXLEN ~ N` to cap stream length.
- Uses the existing `RedisBus` connection (M1 already holds an `aioredis.Redis` instance).
- Payload: same `event_payload` shape as HTTP (spec §8); serialized as JSON in a `data` field of the stream entry.
- Retry: **reuses `core/notifier/retry.py`** — does not fork the policy. 3 attempts, exponential backoff (matches `HttpChannel`). Trim failures (`MAXLEN` operations) log a warning but do not fail the delivery.

### 4.5 `WebSocketChannel` + `/ws` server

- Channel config: `{ws_fanout_channel: str}` — a Redis Pub/Sub channel name that the WS server subscribes to. Pub/Sub is at-most-once: messages are dropped when no client is connected, and there is no replay. This matches spec §2 (no auth/no backfill non-goals) and is intentional — WS clients are observability listeners, not source-of-truth consumers. If at-least-once is needed, the same subscription can also be bound to a `RedisStreamsChannel`.
- `WebSocketChannel.send(payload)` → `redis.publish(ws_fanout_channel, json.dumps(payload))`. Retry reuses `core/notifier/retry.py` (3 attempts on `RedisError`).
- `/ws?channel_id=<uuid>` handler in `apps/web/routers/ws.py`:
  - Resolves `channel_id` → `ws_fanout_channel` via `ChannelRepo`.
  - Subscribes to that Redis pubsub channel.
  - Streams every published message to the connected client via a bounded `asyncio.Queue(maxsize=256)`.
  - Multiple clients per `channel_id` allowed (Redis pubsub fans out natively).
- **Back-pressure**: a slow client whose queue is full causes the dispatcher to drop messages for that client; a single warning is logged per client per 60s window. Other clients on the same channel are unaffected.

### 4.6 `SolanaAdapter`

```python
class SolanaChainAdapter(Protocol):
    """Distinct from `core/chains/adapter.ChainAdapter` (EVM); they intentionally
    diverge on field names (`commitment` vs `confirmations`) and block shape
    (`SolanaBlock` vs `Block`)."""
    chain_id: str
    commitment: Literal["confirmed", "finalized"]   # from chain config

    async def connect(self) -> None: ...
    async def disconnect(self) -> None: ...
    async def get_latest_slot(self) -> int: ...
    async def fetch_block(self, slot: int) -> SolanaBlock | None: ...
    def subscribe_heads(self) -> AsyncIterator[BlockHeader]: ...
```

- The existing `ChainAdapter` Protocol stays EVM-typed (`confirmations: int`, `fetch_block(number)`, returns `Block`). Solana gets its own Protocol. `apps/worker/main.py:_default_adapter_factory` branches on `cfg.kind`: `"evm"` → `EvmAdapter`, `"solana"` → `SolanaAdapter`. Two ChainRunner instantiations are not required — `ChainRunner` is generalized to take `EvmChainAdapter | SolanaChainAdapter` plus a "pipeline kind" that picks which `ParserPipeline` to run.
- **Note on parent spec divergence:** spec §4.4 lists `solana-py + solders` for the Solana stack. M2 ships only `solders + httpx` for transport. This is a deliberate scope tightening — `solana-py` brings a sync-first surface and we don't need it; `solders` already provides typed RPC requests/responses. If a future feature requires `solana-py` we revisit.
- RPC client: `solders` for type-safe RPC + `httpx.AsyncClient` for transport.
- `subscribe_heads` polls `getSlot` at the configured commitment every `poll_interval_ms`.
- `fetch_block` calls `getBlock` with `maxSupportedTransactionVersion=0`, `transactionDetails="full"`, `rewards=false`.
- **No `ConfirmationBuffer`** — commitment level guarantees finality at the configured level. Reorgs above `confirmed` are vanishingly rare; the buffer would only add latency.
- `SolanaBlock` shape: `slot`, `block_hash`, `block_time`, `transactions: list[SolanaTransaction]`. Each tx carries `meta.pre_balances`, `meta.post_balances`, `meta.pre_token_balances`, `meta.post_token_balances`, `meta.log_messages`, `transaction.message.account_keys`, `transaction.message.instructions`.
- **Migration:** the existing `chains` table has `confirmations: int` (EVM only). M2 adds a nullable `commitment: str` column via a one-line Alembic migration in chunk 10. Solana rows set `commitment`; `confirmations` is left at its default (0 for new Solana rows, untouched for existing EVM rows). The API validates that EVM chains supply `confirmations` and Solana chains supply `commitment`.

### 4.7 Solana parsers and the parser-pipeline split

The M1 `NativeTransferParser` docstring claims SolanaAdapter normalizes Solana txs into the EVM `Tx` shape so the parser is "chain-agnostic". **M2 retracts that claim**: Solana txs have a fundamentally different shape (`pre_balances` / `post_balances` for native moves, instruction walking, base64-encoded `Program data:` log lines), and forcing the EVM `Tx` shape onto Solana would lose information needed by SPL and Anchor parsers.

Concrete split:

- `core/parser/pipeline.py` becomes generic over the block type: `EvmParserPipeline(parsers: Sequence[EvmParser])` consumes `Block`, `SolanaParserPipeline(parsers: Sequence[SolanaParser])` consumes `SolanaBlock`. Both yield the same `Event` shape.
- `ChainRunner` picks pipeline by `chain.kind`. The matcher and notifier are downstream and unchanged.
- Solana parsers:
  - `SolNativeTransferParser` — walks `instructions` for `system_program::transfer`; emits `kind="native_transfer"` with `{from, to, value}` in lamports. Skips inner instructions where program ≠ System Program. Skips failed txs (`meta.err is not None`).
  - `SplTransferParser` — walks `instructions` for `spl_token::Transfer` / `spl_token_2022::Transfer`; emits `kind="token_transfer"`; resolves mint via `meta.post_token_balances` (more reliable than walking accounts).
  - `AnchorIdlEventParser` — scans `meta.log_messages` for `Program data: ...` lines; base64-decodes; first 8 bytes is the discriminator; checks the surrounding `Program <program_id> invoke` line to scope the lookup to a specific program (mitigates the rare cross-program discriminator collision noted in §9.2); looks up event schema in `AbiRegistry`; borsh-decodes the rest. Emits `kind="event"`.

### 4.8 `arg_filters` — Pydantic value-type tightening only

M1 already implements the full filter grammar (`eq` / `_in` / `_gte` / `_lte`) with case-insensitive string compare and typo rejection in `core/matcher/filters.py`. The matcher already calls `evaluate(sub.arg_filters or {}, event.args)` at every match attempt. **M2 does NOT change matcher logic.**

The remaining gap is at the API boundary: the Pydantic `SubscriptionCreate.arg_filters: dict[str, Any]` schema accepts any JSON value, but `filters.evaluate` will error or silently mis-match if a downstream value is e.g. a nested dict. Chunk 9 tightens the schema to:

```python
ArgFilterValue = str | int | bool | list[str | int | bool]
arg_filters: dict[str, ArgFilterValue] = Field(default_factory=dict)
```

…and runs `filters.validate(arg_filters)` (existing function) inside the Pydantic validator so the typo grammar fires at API time, not at parse-time. Existing rows that survive validation are unchanged; rows that fail surface in a one-shot migration check (chunk 9 ships a `scripts/validate_arg_filters.py` that prints offenders for operator review).

### 4.9 `EventKind` ↔ `MatchKind` rename

M1 left a latent drift: `core/parser/event.py:6` declares `EventKind = Literal["native_transfer", "token_transfer", "log", "call"]`, while `core/config/models.py:36` (`MatchKind`) has `event` instead of `log`. The matcher keys on string equality, so an `AbiEventParser` that emits `kind="log"` would never match a subscription with `match_kind="event"`.

**Resolution in chunk 4:** rename `EventKind.log → event`. This is a single-character literal change in `event.py` plus updates to the only callers (the parser stub if any, and tests). No DB / API schema change. The decode-failure downgrade in §4.1 also re-targets `kind="event"` so unknown-topic logs surface as `kind="event"` with `name=None` rather than silently lost.

## 5. Data Flow — Per Chain Kind

### EVM (unchanged from M1, with new parsers in the pipeline)

```
EvmAdapter → BlockHeader → ConfirmationBuffer → confirmed Block
  → ParserPipeline (native, erc20, abi_event, abi_call all consume same Block)
  → Event[]
  → Matcher (chain_id, address, match_kind, match_name, arg_filters)
  → (Subscription, [Channel]) pairs
  → Notifier → Channel.send(payload)
```

### Solana

```
SolanaAdapter (commitment-bound poll) → SolanaBlock | null
  null  → checkpoint += 1 slot (missed slot)
  block → SolanaParserPipeline (sol_native, spl, anchor_event consume SolanaBlock)
  → Event[] (same uniform shape as EVM)
  → Matcher (same code path; chain_id picks Solana subs)
  → Notifier → Channel.send(payload)
```

The matcher and notifier are common code; only the adapter + parser pipeline differ. The two pipelines (`EvmParserPipeline`, `SolanaParserPipeline`) are concrete classes selected by `ChainRunner` based on `chain.kind`.

## 6. Error Handling Deltas

| Failure | M2 behavior |
|---|---|
| ABI missing for `abi_id` referenced by a subscription | Log warning, skip parsing that subscription's matches; do NOT block the pipeline. |
| ABI decode failure | Downgrade to `kind="event"` (post-§4.9 rename) with `name=None` and raw payload preserved in `event.raw`. |
| Solana RPC 429 / timeout | Reuse `core/notifier/retry.py` (`tenacity` exponential backoff, max 3). After max retries, log and **skip block but advance checkpoint** if-and-only-if a separate `getBlock` returns clean — see next row. |
| Solana `getBlock(slot)` returns `null` (missed slot — Solana slots ≠ blocks) | **Advance checkpoint by one slot** and continue. This is the not-an-error case. |
| Solana RPC error vs missed slot — disambiguation | A `null` block result (HTTP 200) → missed slot (advance). A 4xx/5xx response or transport error → retry (do not advance). The two paths use different `solders` response variants and never collide. |
| WebSocket client buffer full | Server drops the message for that client (no per-client retry); one log warning per client per 60s. Other clients on the same channel are unaffected. |
| Redis Streams `MAXLEN ~` trimming | Best-effort; trim failures log a warning but do not fail the delivery. |
| Anchor IDL discriminator collision across programs | Resolved by program ID: `AnchorIdlEventParser` scopes lookup to the `program_id` the `Program data` line was emitted under (extracted from the preceding `Program <pid> invoke` log line). |

## 9. Open Decisions / Risks

### 9.1 M1 follow-ups disposition

Originally listed as nine items. Five close in chunk 1; three graduate into the chunks that naturally touch their files; one stays "tracked only".

**Closed in chunk 1 (5 items):**
1. **Parallel `_Worker.shutdown` runner stops** — use `asyncio.gather(*[r.stop() for r in runners])` instead of the current sequential loop. Constraint: bus disconnect **must** happen strictly after `gather` returns (current ordering); gather collapses runner stops, not the bus-stop ordering.
2. **`Notifier._sem` event-loop binding** — build `asyncio.Semaphore` on first `send()`, not in `__init__`, so the bound loop matches the running loop.
6. **`poll_interval_ms` per-chain plumbing into `EvmAdapter`** — currently hard-coded to 1s. Read `chain.poll_interval_ms` and pass through `EvmAdapter(poll_interval_ms=...)`.
8. **Friendlier `KeyError` / Windows signal handler docstring polish** — `apps/worker/main.py` signal handlers swallow `NotImplementedError` on Windows; comment clarifies the loop-platform interaction.
9. **Deterministic worker-ready signal in E2E** — replace `await asyncio.sleep(1.0)` in `tests/e2e/test_native_transfer_e2e.py` with a barrier the worker flips when its first poll loop iteration completes.

### 9.2 Risks

- **`solders` API churn.** `solders` is the modern Solana Python client but its API is less stable than `web3.py`. Risk: a version bump breaks the adapter. Mitigation: pin to a tested minor version; add `solders` to dev deps with a tight constraint; rely on `solana-test-validator` IT for early breakage detection.
- **`borsh-construct` library churn.** Same risk class as `solders` for the Anchor IDL decode path. Mitigation: pin to a tested minor; the decoder is unit-tested with a fixed-schema fixture so library API breakage surfaces immediately.
- **Anchor IDL discriminator collisions.** Across multiple programs, two different events could share an 8-byte discriminator (probability vanishingly low but non-zero). Mitigation: scope discriminator lookup to a specific `program_id` per `AbiRegistry` entry, using the preceding `Program <pid> invoke` log line to identify the emitting program (see §4.7).
- **WebSocket back-pressure.** Slow clients can hold up Redis pubsub fanout. Mitigation: per-client bounded `asyncio.Queue(maxsize=256)`; drop-on-full with a single logged warning per client per minute.
- **`arg_filters` schema break risk against existing M1 rows.** M1 accepts arbitrary dicts at the API but `filters.validate` already enforces typo-grammar. Strict value-type Pydantic validation in chunk 9 could reject existing data on read-back if any operator inserted nested values via the SQL layer. Mitigation: chunk 9 includes `scripts/validate_arg_filters.py` that runs against the live DB and prints offenders; chunk acceptance gate is "scanner reports zero offenders against current test fixtures".
- **`solana-test-validator` cold-start time** in E2E (5–10s vs Anvil's <1s). Mitigation: scope it as session-scoped fixture (different from M1's function-scoped `anvil`); document slower local feedback.
- **EVM ↔ Solana pipeline split duplicates plumbing.** Two `ParserPipeline` classes mean two construction call-sites in `ChainRunner`. Acceptable cost — keeps each parser strongly typed against its block shape. If a third chain kind shows up, revisit (likely with a generic base + per-kind concrete subclasses).

### 9.3 Things deliberately deferred and why

- **Persisted `events` table for replay.** Spec §10 mentions it for observability/M5. M2 stays stateless on the event stream because adding persistence here would couple the notifier to DB latency and obscure delivery semantics.
- **Per-channel retry policy customization.** M2 inherits the M1 hard-coded `3 attempts, exponential backoff`. Per-channel YAML knobs are an M3 ergonomic improvement.
- **Anchor IDL call parser.** Skipped because Anchor instruction decoding requires walking `instructions[]` with account-key resolution; doing it right takes its own chunk. The event parser handles 80%+ of observability use cases.
- **`m2-evm-complete` interim tag.** Chunk 9 closes with this tag. If Solana slips, M2 can ship as M2.5 with only the EVM segment. The Solana chunks (10–14) stay strictly additive — no chunk before #10 imports anything from `core/chains/solana.py` or `core/parser/sol_*`, so the EVM tag is a true release point.
- **`core/notifier/payload.py` extension for new `kind` values.** The existing `event_payload` builder is `kind`-agnostic (it just serializes the `Event` dataclass to dict); `token_transfer`, `event`, and `call` all flow through unchanged. No work needed in M2; called out here to close the loop.
